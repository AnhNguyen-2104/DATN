## 2. Technical Remediation Details

### 2.1 Elimination of `nBeltCommandResult` Writes
* **Root Cause:** In the previous pass, WPF attempted to clear stale results by writing `_transport.TryWrite("MAIN.nBeltCommandResult", (ushort)0)`. This violated ownership because `MAIN.nBeltCommandResult` is generated by `MAIN.TcPOU` logic. Writing to it created a cross-owner race with the PLC task.
* **Fix:** Completely eliminated all writes to `nBeltCommandResult` from `LineMailboxProtocol.cs`. WPF now treats `MAIN.nBeltCommandResult` as strictly read-only telemetry.

### 2.2 Alignment with TwinCAT Manual Belt Sequence Contract
* **New Contract Symbols (from `Docs/TWINCAT_MANUAL_BELT_MAILBOX_SEQ_CONTRACT_20261023.md`):**
  * `MAIN.udiHmiBeltCmdSeq` : UDINT (WPF writer). Non-zero, monotonic sequence.
  * `MAIN.udiBeltLastAckSeq` : UDINT (PLC writer/readback). Set by PLC when pulse is processed.
  * `MAIN.nBeltCommandResult` : UINT (PLC writer/readback). 1=accepted, 10=duplicate/zero seq, 11=not commissioned, 12=interlock/stale, 13=invalid setpoint, 14=outside 25Hz limit, 18=revoked.
* **WPF Handshake Flow:**
  1. Allocate fresh non-zero sequence: `seq = AllocateManualSequence()`.
  2. Write `MAIN.udiHmiBeltCmdSeq := seq`.
  3. Write parameters (e.g. `MAIN.rHmiBeltSetSpeed_mm_s := speedMmS` for SET).
  4. Assert request pulse (`bHmiBeltSetReq`, `bHmiBeltStartReq`, or `bHmiBeltStopReq`).
  5. Hold pulse for `PulseHoldMs = 30 ms` ($\ge 2-3$ PLC scans of nominal 10ms task).
  6. Poll `MAIN.udiBeltLastAckSeq == seq` within `AckTimeoutMs = 600 ms`.
  7. In `finally` block, deassert request pulse to `FALSE`.
  8. If `ackSeq == seq && result == 1` $\to$ Command accepted.
  9. If `ackSeq != seq` $\to$ Command timed out.
  10. If `result != 1` $\to$ Command rejected with specific error description.

### 2.3 Guaranteed Pulse Deassertion under Cancellation & Exceptions
* **Root Cause:** Previously, if a timeout, task cancellation, or unexpected exception occurred during `Task.Delay` or polling, execution jumped to the outer catch block, leaving the request pulse stuck at `TRUE` in the PLC process image.
* **Fix:** Wrapped every pulse assertion in `try ... finally`:
  ```csharp
  if (!_transport.TryWrite("MAIN.bHmiBeltSetReq", true, out var errReq))
      return new CommandDispatchResult(false, 12, $"MANUAL SET FAILED: Could not assert set request: {errReq}");

  try
  {
      // Bounded pulse hold & ACK polling
  }
  finally
  {
      _transport.TryWrite("MAIN.bHmiBeltSetReq", false, out _);
  }
  ```
  Verified via unit test: cancelling a `CancellationToken` during pulse hold guarantees that `bHmiBeltSetReq` is written back to `FALSE`.

### 2.4 Strict SET $\to$ START Ordering
* `RequestManualBeltStartAsync` enforces:
  ```csharp
  if (!_priorBeltSetAccepted || Math.Abs(_lastAcceptedBeltSetMmS - speedMmS) > 0.05)
  {
      return new CommandDispatchResult(false, 12, $"MANUAL START BLOCKED: Setpoint {speedMmS:F1} mm/s has not been acknowledged by prior SET. Issue SET first.");
  }
  ```
  The operator must explicitly issue and receive an accepted SET before START can be dispatched.
